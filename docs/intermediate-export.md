# 工具栏中间结果导出

右键缩放输出工具栏的截图按钮，可选择每个效果的输出。条目显示链中的顺序、效果名和实际输出尺寸。普通截图左键/配置快捷键行为不变。尚无算法帧时，菜单只显示等待状态。

当前读取 Vulkan 链每个效果完成后的 RGBA8 输出缓冲，包括为呈现追加的重采样阶段。不是把最终图片再次缩放成某个中间尺寸，也不会重新执行算法。开发者模式增加原始 pass / 多纹理子菜单，见下节；普通模式仍直接导出各效果完成的结果。

新增 32 字节 `mp_stage_snapshot_info` 和 `mp_stage_snapshot` / `mp_copy_stage_snapshot` C ABI。每次成功执行具有新的序号和有效阶段数量；进入可能改变资源的执行前失效旧结果。只允许读取匹配序号、有效阶段及精确字节数。失败不改调用者像素；新执行/缩短链后，旧序号或旧索引会被拒绝。

现有输出缓冲为 HOST_VISIBLE | HOST_COHERENT。计算写入增加 host-read 可见性，继续保留下一阶段传输读取的依赖；已有 fence 完成后读取，没有额外命令提交或 profiler 采样。同步依据：[Khronos Vulkan 同步与内存可见性](https://docs.vulkan.org/spec/latest/chapters/synchronization.html)。

导出与渲染共用异步门：工作线程持有它完成 GPU 执行及对应 UI 位图/源身份提交；UI 等待时不阻塞工作线程完成该提交。取得门后冻结当前显示的链、源身份和像素读取，期间不会被下一帧覆盖。若菜单选择的效果已不在该索引，报错要求重新选择。停止或读回失败不保存，目标目录错误会显示消息并允许重试。

文件仍采用当前配置的截图目录和模板，追加 `stage序号_效果名` 标识并保留重名保护；完整组件限制为 220 字节主体加 `.png`，UTF-8 不截断字符，并为冲突后缀留空间。效果标识先保留，再截短长窗口名，避免所有导出文件的阶段标识被长标题挤掉。

本轮证据为 `artifacts/desktop/stage-export-test-summary.json`：Linux NativeAOT / 实际 Vulkan、独立 nearest/bicubic 比较及 NNEDI3 最终缓冲一致性、序号/边界/失败不写保护、23 CTest 和中英隔离 UI。UI 使用真实菜单 handler、真实 Vulkan / PNG / 文件系统，捕获身份/输入与 worker 等待为注入场景；关闭测试输出后，在录制窗口重新生成相同菜单用于原生 popup 图层取证，不把这个取证窗口当作真实输出窗口指针验收。

隔离 Wayland 截图现记录实际视觉树的内容区→顶层表面偏移，和已 ack/commit 的 xdg_popup 坐标合成；不猜测标题栏/阴影高度。新增装饰窗口偏移、内容越界及缺失 transform 的解析器用例。合成图不是合成器 framebuffer 截屏。

本轮 Windows/macOS 新 C ABI 编译、GPU 读回、真实右键/辅助功能/多 DPI 行为仍需相应提交的目标机验证，不能沿用此前截图快捷键提交的通过记录。完整交互清单保持未完成。

## 开发者逐 pass / 多纹理导出

在 About 激活开发者选项后，开发者模式保存到配置；关闭模式隐藏开发者区。原版配置的 `developerMode` 也会迁移。截图右键菜单在多 pass 效果下展开原版 pass 描述，多个输出再按原始纹理名展开。描述、顺序、纹理索引和格式由原始 MagpieFX 生成，覆盖已注册的 111 个 graph；简单效果仍直接导出最终 PNG。

最后一个 pass 读取已完成的 RGBA8 输出并保存 PNG。内部输出保存 DX10 DDS，保留 RGBA16F、RGBA8、R16F、RG16F、R8 或 RG8 原始通道字节，不将浮点/负数归一化为预览色。当前原版可写输出覆盖其中五种，R8 仅用于 SOURCE 资源；DDS 写入器的六种格式另有独立解码检查。

新增 56 字节 `mp_pass_snapshot_info` 与查询/复制 API。早期 pass 的纹理可能已被后续 pass 覆盖，因此内部输出会在渲染互斥门内按当前帧的输入、参数重新执行到所选 pass，再做 Vulkan transfer readback。这部分会额外提交 GPU 工作；不更新已显示帧的序号、FPS 或 profiler 缓存，也不改最终输出缓冲。不能沿用普通阶段导出“不额外执行 GPU”的描述。查询和复制均检查执行序号、pass、纹理、格式和精确字节数，拒绝过期/失配请求。

DDS 与 PNG 共用源身份、目录、模板、阶段和 pass 后缀及重名保护。DDS 先写同目录临时文件再以不覆盖方式移动；失败清理临时文件并恢复导出状态，关闭开发者模式后拒绝旧 pass 命令。

本阶段 Linux 最终 NativeAOT、23/23 CTest、交互模型、六种 DDS 独立解码及七项中英宽/窄私有 Wayland UI 通过，报告 `artifacts/desktop/pass-export-test-summary.json`。UI 执行实际菜单 handler 并比较七个 DDS/PNG 与 native pass 数据，覆盖开发者激活/关闭、旧命令拒绝、写入失败重试和临时文件清理；源像素/身份及点击事件为注入。关闭功能测试输出后，录制窗口重新生成菜单，三个实际 native popup 的 ack/commit 坐标均在内容区内；已查看宽/窄合成图。同步验证请求下 Khronos validation layer 确认加载，核心通过且未报告 VUID/同步错误。原生 GPU 用例已覆盖 15 个 pass 输出，包括 Anime4K 多输出/纹理复用重放、NNEDI3 R16F 偶数行的独立亮度期望、SMAA 不同通道格式、最终缓冲保留和后续正常渲染。这个范围不证明所有算法的数值对齐，也不证明真实三平台鼠标和菜单交互。

三级菜单定位以父菜单相对原窗口的位置逐层约束，空间不足时优先向左展开；不依赖 Wayland 全局窗口坐标。修复前的底边越界由原生 popup 取证实际检出，没有放宽图像边界检查。Windows/macOS 当前提交仍待 CI 原生编译和目标机实际读回/交互验收，完整目标保持未完成。
